Вопрос 1: Назначение Node.js во фронтенде и почему он не работает в браузере при CSR
Во фронтенд-разработке Node.js нужен для подготовки и сборки проекта перед тем, как сайт увидит пользователь. Браузер понимает только базовые технологии (HTML, обычный CSS и стандартный JavaScript) и не умеет напрямую работать с современными инструментами разработчика. Node.js запускается на компьютере программиста или на сервере сборки, где он может читать и изменять файлы на диске.
Задачи, которые решает Node.js во фронтенде:
Компиляция JSX и TypeScript. Разработчики пишут код с использованием удобного синтаксиса JSX (смесь HTML и JS в React) и строгой типизации TypeScript. Специальные программы-переводчики (Babel, TypeScript-компилятор), работающие на базе Node.js, берут эти файлы, вырезают из них типы и переписывают JSX в обычный JavaScript, который сможет прочитать любой браузер.
Парсинг CSS-модулей. Когда стили пишут в CSS-модулях, имена классов в разных файлах могут случайно совпасть и сломать верстку. Сборщики (Webpack или Vite) с помощью Node.js читают такие файлы, автоматически добавляют к названиям классов случайные наборы букв и цифр для уникальности, а затем связывают их с нужными компонентами.
Минификация бандлов. Во время разработки проект состоит из сотен отдельных файлов с отступами, длинными названиями переменных и комментариями. Перед публикацией сайта инструменты на базе Node.js склеивают все файлы в несколько общих (бандлов), удаляют все пробелы, комментарии, неиспользуемый код и сокращают имена переменных до одной буквы. Это сильно уменьшает вес файлов, чтобы сайт быстрее загружался по интернету.
Локальный HTTP-сервер разработки. Чтобы программист мог сразу видеть результат своей работы, Node.js запускает на его компьютере мини-сервер. Этот сервер раздает файлы проекта браузеру и следит за сохранениями. Как только разработчик меняет строку кода и нажимает «Сохранить», сервер мгновенно обновляет этот кусочек на странице в браузере без полной перезагрузки.
Почему Node.js не исполняет код React в браузере клиента при CSR?
При CSR (Client-Side Rendering — отрисовка на стороне клиента) сервер отправляет пользователю почти пустую HTML-страницу и ссылку на готовый JavaScript-файл. Дальше всю страницу строит сам браузер. Node.js в этом процессе не участвует по трем причинам:
На устройстве пользователя нет Node.js. Обычный посетитель сайта заходит на него через Chrome, Safari или другой браузер со своего телефона или ноутбука. У него не установлена серверная программа Node.js, поэтому запускать код просто нечему.
Разные возможности и окружение. Внутри браузера есть свой движок, который умеет управлять элементами на экране (DOM), менять адресную строку, следить за кликами мыши и работать с окном браузера (window, document). У Node.js таких инструментов вообще нет — он создан для работы с файлами на жестком диске, сетью и операционной системой.
Работа Node.js заканчивается на этапе сборки. Как только Node.js собрал, перевел и сжал все файлы проекта в готовую папку, его миссия выполнена. Браузер скачивает эти готовые файлы и сам запускает React внутри себя.

Вопрос 2: Статические методы Object и разница между собственными и унаследованными свойствами
В JavaScript у объектов нет встроенных удобных методов для перебора, как у массивов (например, map или filter). Статические методы Object решают эту проблему, превращая объект в массив, с которым легко работать, и позволяя собрать объект обратно.
Как работают статические методы:
Object.keys(obj) — берет объект и возвращает обычный массив, состоящий только из названий (ключей) его свойств в виде строк.
Object.values(obj) — берет объект и возвращает массив, состоящий только из значений его свойств. Порядок значений совпадает с порядком ключей.
Object.entries(obj) — возвращает массив, где каждый элемент является маленьким массивом из двух элементов: [ключ, значение]. Это удобно, когда нужно одновременно работать и с именем свойства, и с его содержимым.
Object.fromEntries(iterable) — делает действие, обратное Object.entries(). Метод принимает список пар [ключ, значение] (например, массив массивов или коллекцию Map) и собирает из них новый полноценный объект.
Разница между собственными перечисляемыми свойствами и свойствами цепочки прототипов
Все три метода (keys, values, entries) работают только с собственными перечисляемыми свойствами объекта. Чтобы понять, что это значит, нужно разделить свойства на две группы.
Собственные перечисляемые свойства (Own Enumerable) — это обычные свойства, которые записаны непосредственно в сам объект при его создании или добавлены в него позже. При этом они не скрыты специальными настройками. Например, если создать объект пользователя с полями «имя» и «возраст», оба этих поля будут его собственными и видимыми при переборе. Именно их и забирают методы Object.keys, Object.values и Object.entries.
Свойства цепочки прототипов — это свойства и методы, которые сам объект не хранит, но получает «в наследство» от своего родителя (прототипа). Например, у любого объекта можно вызвать метод .toString(), хотя мы его туда не записывали — он берется из базового прототипа JavaScript. Статические методы Object полностью игнорируют такие унаследованные свойства, чтобы не смешивать данные пользователя со служебными функциями языка.
Кроме того, у любого свойства внутри объекта есть невидимый переключатель видимости при переборе (флаг enumerable). Если программист специально сделает свойство неперечисляемым (скрытым), то даже если оно собственное, методы Object.keys, Object.values и Object.entries его проигнорируют. Точно так же они игнорируют свойства, названия которых заданы через специальный тип данных Symbol.
В этом главное преимущество методов Object перед старым циклом for...in. Цикл for...in перебирает вообще все видимые свойства, включая те, что пришли из цепочки прототипов, из-за чего приходится писать дополнительные проверки. Методы Object.keys, Object.values и Object.entries сразу дают только чистые личные данные самого объекта.
